# SDD Specify: 仕様作成コマンド

SDD（仕様駆動開発）の最初のステップ。要件をヒアリングし、仕様書（Part 1）を作成する。

## 入力

ユーザーの要件概要: $ARGUMENTS

## 実行手順

### 1. SDD原則の読み込み

`.claude/skills/sdd-principles/SKILL.md` を読み込み、以下を確認する:
- SDD の5つの基本原則
- プロジェクト憲法（条I〜条IX）
- フェーズゲート定義（ゲート1: Specify → Plan）
- 不確実性マーカー仕様

### 2. テンプレートの読み込み

`.claude/skills/sdd-specify/template.md` を読み込み、仕様書のフォーマットを確認する。

### 3. 要件の把握

ユーザーの入力（`$ARGUMENTS`）から要件の概要を把握する。

- `$ARGUMENTS` が空または不十分な場合: ユーザーに要件の概要を質問する
- `$ARGUMENTS` が十分な場合: 次のステップへ進む

### 4. 要件ヒアリング

ユーザーに質問して要件を明確化する。

**ルール**:
- 不明点は推測せず、質問する
- 質問は具体的に（「要件は？」ではなく「ログイン失敗時のリダイレクト先は？」のように）
- 一度に最大3問まで質問する
- 回答を得たら仕様に反映し、まだ不明点があれば追加質問する

### 5. コードベース調査

要件に関連する既存コードを調査する:
- 影響を受けるファイルの特定
- 既存のパターン・慣習の確認（`.claude/rules/` のルールも参照）
- 既存のAPI契約との整合性確認
- 使用中の依存パッケージの確認

### 6. 仕様書作成

テンプレートの **Part 1（仕様セクション）** を記入し、`.steering/[YYYYMMDD]-[name].md` に保存する。

記入するセクション:
- 1.1 概要（目的、スコープ、動機）
- 1.2 詳細仕様（機能要件テーブル、API契約、データモデル）
- 1.3 受入基準（Given-When-Then テーブル）
- 1.4 エッジケース
- 1.5 制約事項（セキュリティ、パフォーマンス、依存関係）
- 1.6 テスト戦略
- 1.7 不確実性（未解決の `[NEEDS CLARIFICATION]` 一覧）
- 1.8 プロジェクト憲法チェックリスト

**注意**:
- Part 2（実装計画）はこのステップでは記入しない
- 不明点は `[NEEDS CLARIFICATION: 質問]` マーカーで記録する
- API契約はメソッド・パス・リクエスト形式・レスポンス形式・ステータスコードを全て記載する

### 7. プロジェクト憲法チェックリスト検証

仕様書の 1.8 プロジェクト憲法チェックリストを検証する:
- 各条項（条I〜条IX）に対して、仕様が準拠しているか確認
- 該当しない条項には理由を備考に記載
- 準拠している条項にチェックを入れる

### 8. フェーズゲート1 確認

ゲート1（Specify → Plan）の通過条件を確認する:

| # | 条件 | 確認方法 |
|---|------|---------|
| G1-1 | `[NEEDS CLARIFICATION]` マーカーがゼロ | 仕様書内を検索 |
| G1-2 | 受入基準が1つ以上存在 | Given-When-Thenテーブルを確認 |
| G1-3 | プロジェクト憲法チェックリストが全項目記入済み | チェックボックスを確認 |

**未通過の場合**: 未解決の不確実性をユーザーに提示し、解決を求める。解決後にゲートを再確認する。

**通過した場合**: ステップ9へ進む。

### 9. ユーザー承認

仕様書の内容をユーザーに提示し、承認を待つ。

提示する内容:
- 仕様書の概要サマリー
- 受入基準の一覧
- フェーズゲート1の通過状況
- 保存先ファイルパス

## 次のステップ

承認後、ユーザーに次のステップを案内する:

> 仕様書が承認されました。次のステップとして `/sdd-plan` を実行し、実装計画を作成してください。
>
> ```
> /sdd-plan [仕様書ファイル名]
> ```

## 出力

- `.steering/[YYYYMMDD]-[name].md` に仕様書（Part 1）を保存
- フェーズゲート1の通過状況を報告

## 注意事項

- このコマンドではコードの変更は行わない（仕様書の作成のみ）
- 仕様は `.steering/` に保存され、計画フェーズで同じファイルに追記される
- 仕様書のステータスは「Draft」→「Approved」で管理する
