# SDD Implement: 実装実行コマンド

SDD（仕様駆動開発）の最終ステップ。計画書（Part 1 + Part 2）に基づいてステップバイステップで実装を進める。

## 入力

対象の仕様書ファイル名（任意）: $ARGUMENTS

## 前提条件

- `/sdd-specify` で仕様書（Part 1）が作成済みであること
- `/sdd-plan` で実装計画（Part 2）が作成済みであること
- `.steering/` ディレクトリに対象の計画書が存在すること

## 実行手順

### 1. SDD原則の読み込み

`.claude/skills/sdd-principles/SKILL.md` を読み込み、以下を確認する:
- SDD の5つの基本原則
- プロジェクト憲法（条I〜条IX）

### 2. 計画書の特定と読み込み

対象の計画書を特定する:

```
$ARGUMENTS の内容は？
├── ファイル名が指定されている → そのファイルを .steering/ から読み込む
└── 空 / 指定なし → .steering/ 内のファイル一覧を表示し、ユーザーに選択を求める
```

計画書の Part 1（仕様）と Part 2（実装計画）の両方を読み込む。

### 3. フェーズゲート2 検証

ゲート2（Plan → Implement）の通過条件を検証する:

| # | 条件 | 確認方法 |
|---|------|---------|
| G2-1 | ゲート1を通過済み | 仕様書のステータスと Part 1 の完成度を確認 |
| G2-2 | 実装フェーズが定義されている | Part 2 の 2.3 セクションを確認 |
| G2-3 | 各タスクに完了条件がある | 各タスク定義の完了条件カラムを確認 |
| G2-4 | シンプリシティゲートが確認済み | 計画書の 2.4 を確認 |
| G2-5 | ユーザーが計画を承認済み | 明示的な承認を確認 |

**未通過の場合**: 未達成の条件を具体的に報告し、以下を案内して中止する:

> フェーズゲート2を通過できません。`/sdd-plan` で計画を修正してください。
>
> 未達成の条件:
> - [具体的な未達成条件を列挙]

### 4. 進捗確認

計画書のチェックボックスと進捗サマリー（2.1）を確認する:

```
進捗状況は？
├── 全タスクが未着手 → フェーズ1の最初のタスクから開始
├── 一部完了済み → 未完了の最初のタスクから再開
│   └── 完了済みステップの概要をユーザーに報告してから再開
└── 全タスク完了済み → ステップ7（全完了時）へ進む
```

### 5. ステップバイステップ実装

各タスクを以下の手順で実装する:

1. **タスク宣言**: 実行するタスクの内容をユーザーに報告
2. **テスト先行**（条III）: テストが必要なタスクではテストを先に作成
3. **実装**: コードを作成・変更
4. **検証**: 完了条件を満たしているか確認（テスト実行を含む）
5. **進捗更新**: 計画書のチェックボックスを `- [x]` に更新
6. **次のタスクへ**: 依存関係を確認し、次のタスクに進む

**SDD固有ルール**:
- **計画にない変更の禁止**: 計画書に記載のないファイル変更・機能追加は行わない。必要な変更を発見した場合は、ユーザーに報告して仕様への追加を提案する
- **受入基準による完了判定**: 「動いているから完了」ではなく、仕様通りであることを確認する

### 6. フェーズ完了時

各フェーズが完了したら:
1. 進捗サマリー（2.1）を更新（ステータスを「完了」に変更）
2. 実装ログ（2.7）に記録を追加（日時、ステップ、ステータス、備考）
3. ユーザーに完了を報告し、次のフェーズへ進むか確認

### 7. 全完了時

全フェーズが完了したら:
1. 計画書の進捗サマリー（2.1）を最終更新
2. 成功基準（2.6）の達成状況を確認
3. 最終レポートを作成:
   - 変更ファイル一覧
   - 成功基準の達成状況
   - 推奨される次のステップ（テスト実行、コードレビュー等）

## ブロッカー時の対応

実装中にブロッカーが発生した場合:

```
ブロッカーの原因は？
├── 仕様の不備 → ユーザーに報告し、/sdd-specify に戻ることを提案
├── 計画の不備 → ユーザーに報告し、/sdd-plan に戻ることを提案
└── 技術的問題 → ユーザーに報告し、解決策を相談
```

全てのブロッカーは実装ログ（2.7）に記録する。

## 中断と再開

- **中断時**: 進捗は計画書のチェックボックスと実装ログに自動保存される
- **再開時**: `/sdd-implement` を再実行すると、計画書の進捗を読み込み、未完了のタスクから再開する

## 出力

- 計画に基づくコード変更
- 計画書の進捗更新（チェックボックス、サマリー、ログ）
- 最終レポート（全完了時）

## 注意事項

- 計画にない変更は行わない
- プロジェクト憲法を常に遵守する
- `.claude/rules/` に定義されたコーディング規約・テスト規約・バックエンド規約に従う
