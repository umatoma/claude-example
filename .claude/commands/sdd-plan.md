# SDD Plan: 実装計画作成コマンド

SDD（仕様駆動開発）の2番目のステップ。仕様書（Part 1）に基づいて実装計画（Part 2）を作成する。

## 入力

対象の仕様書ファイル名（任意）: $ARGUMENTS

## 前提条件

- `/sdd-specify` で仕様書（Part 1）が作成済みであること
- `.steering/` ディレクトリに対象の仕様書が存在すること

## 実行手順

### 1. SDD原則の読み込み

`.claude/skills/sdd-principles/SKILL.md` を読み込み、以下を確認する:
- SDD の5つの基本原則
- プロジェクト憲法（条I〜条IX）
- フェーズゲート定義（ゲート1・ゲート2）

### 2. 仕様書の特定と読み込み

対象の仕様書を特定する:

```
$ARGUMENTS の内容は？
├── ファイル名が指定されている → そのファイルを .steering/ から読み込む
└── 空 / 指定なし → .steering/ 内のファイル一覧を表示し、ユーザーに選択を求める
```

仕様書の Part 1（仕様セクション）を読み込む。

### 3. フェーズゲート1 検証

ゲート1（Specify → Plan）の通過条件を検証する:

| # | 条件 | 確認方法 |
|---|------|---------|
| G1-1 | `[NEEDS CLARIFICATION]` マーカーがゼロ | 仕様書内を `[NEEDS CLARIFICATION` で検索 |
| G1-2 | 受入基準が1つ以上存在 | 1.3 受入基準セクションの Given-When-Then テーブルを確認 |
| G1-3 | プロジェクト憲法チェックリストが全項目記入済み | 1.8 のチェックボックスを確認 |
| G1-4 | ユーザーが仕様を承認済み | ステータスが「Approved」か、ユーザーに明示的な承認を求める |

**未通過の場合**: 未達成の条件を具体的に報告し、以下を案内して中止する:

> フェーズゲート1を通過できません。`/sdd-specify` で仕様を修正してください。
>
> 未達成の条件:
> - [具体的な未達成条件を列挙]

### 4. アーキテクチャ設計

仕様の要件に基づいてアーキテクチャを設計する:
- 新規ファイルの配置（プロジェクト構造に準拠）
- 既存ファイルへの変更
- レイヤー分離の確認（条I: モジュール先行、条VI: 関心の分離）
- データフローの整理

### 5. フェーズ分解

受入基準からアトミックなタスクに分解する:

1. **テスト先行**（条III）: 各フェーズは「テスト作成 → 実装 → 検証」の順序
2. **依存関係**: タスク間の依存関係を明示
3. **完了条件**: 各タスクに受入基準ベースの完了条件を設定
4. **ファイルパス**: 各タスクで変更するファイルを明記

推奨フェーズ構成:
```
フェーズ1: テスト準備（テストヘルパー・フィクスチャ）
フェーズ2: コアロジック（ビジネスロジック）
フェーズ3: インターフェース統合（外部インターフェース層）
フェーズ4: 統合テスト
```

### 6. シンプリシティゲート

条VII（簡潔性ゲート）準拠を事前チェック:
- [ ] 関数・ファイルの行数が上限内に収まる見込み
- [ ] ネスト深度が上限内に収まる見込み

超過が見込まれる場合は、分割方針を計画に記載する。

### 7. リスク評価

実装上のリスクを評価する:
- 技術的リスク（未知のAPI、性能懸念等）
- 依存関係リスク（外部サービス、パッケージ互換性等）
- スコープリスク（要件の曖昧さ、変更の影響範囲等）

### 8. 計画書保存

仕様書の **Part 2（実装計画セクション）** を追記する:
- 2.1 進捗サマリー
- 2.2 アーキテクチャ変更（新規ファイル・変更ファイル）
- 2.3 実装フェーズ（チェックボックス付きアトミックタスク）
- 2.4 シンプリシティゲート
- 2.5 リスク評価
- 2.6 成功基準（Part 1 の受入基準から転記）
- 2.7 実装ログ（空テーブル）

**注意**: 仕様書の Part 1 は変更しない（Part 2 の追記のみ）

### 9. ユーザー承認

計画の概要をユーザーに提示し、承認を待つ。

提示する内容:
- アーキテクチャ変更の概要
- フェーズ一覧とタスク数
- リスク評価のサマリー
- 成功基準の一覧

## 次のステップ

承認後、ユーザーに次のステップを案内する:

> 実装計画が承認されました。次のステップとして `/sdd-implement` を実行し、実装を開始してください。
>
> ```
> /sdd-implement [仕様書ファイル名]
> ```

## 出力

- 仕様書に Part 2（実装計画）を追記
- フェーズゲート2の準備状況を報告

## 注意事項

- このコマンドではコードの変更は行わない（計画の作成のみ）
- フェーズゲート1を通過していない仕様書に対しては計画を作成しない
- 仕様書の Part 1 は変更しない（Part 2 の追記のみ）
